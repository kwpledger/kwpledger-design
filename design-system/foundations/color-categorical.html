Categorical scale

Eight slots for equal-weight categories. Within a register every slot shares one lightness and one chroma; only hue changes. Equal lightness in OKLCH means equal perceived lightness, which is what makes eight colors read as peers rather than as a ranking.

Slots are numbered, never named for their hue. --data-1 is the first slot, not "the red one". Consumers define domain tokens on top (--meal-breakfast: var(--data-1-surface)); this system must never learn what a meal type is.

Three values per slot

Categorized UI is built from pale filled cards with dark text on them, not from text colors. Each slot ships the surface it is filled with, the foreground legible on that fill, and the border that edges it. Ship one value and the consumer derives its own tint immediately — the same drift by a slower route.

Color is reinforcement, never the sole carrier

Every color-coded axis carries a text label beside it. Accessibility requirement and a documented rule — and it is what makes these values safe to change later.

Correct — the category is named in text, and the fill agrees with it.
Wrong — a bare swatch with no label. Invisible to a colorblind reader, and unreadable to anyone who has not been told the key.
Hue placement avoids two bands. Nothing sits at 178–202 (brand teal, where --accent lives) or 238–262 (the navy surface family). A category that looks like the accent reads as interactive; one that looks like navy reads as chrome. Both are meaning collisions. The count is eight and is not meant to grow.

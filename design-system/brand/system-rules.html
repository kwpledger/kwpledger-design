System rules

These are the constraints, not preferences. Each one has a failure mode attached, because a rule whose consequence is invisible gets "tidied" by the next person through.

Three layers, each reaching exactly one down

Palette → semantic → domain. A domain token maps onto a semantic or categorical token, never past it to a raw value.

1 · Palette — --teal-700, --navy-900. Named for what they are. Not for use in components.
2 · Semantic — --accent, --surface, --fg. Named for their job. This is the layer you consume.
3 · Domain — --meal-breakfast, --macro-carbs. Lives in the consuming repo, never in the design system.
Failure mode: the moment an app writes --meal-breakfast: var(--teal-700), the abstraction is dead and re-theming means editing every consumer.

Stately, not neon — chroma ceiling 0.091

Set by --teal-300, the most saturated brand color. Nothing exceeds it. The categorical scale peaks at 0.075, status at 0.085 — status is authored louder than categorical per role, which is what stops an error reading as an ordinary category at the same hue. It is a number a script checks, not a matter of taste.

Failure mode: a value that clips out of sRGB is silently no longer at its authored lightness, which breaks perceptual parity with no warning.

Color is reinforcement, never the sole carrier of meaning

Every color-coded axis carries a text label. Accessibility requirement — and it is what makes these values safe to change later.

Author light and dark together

Neither register is derivable from the other: the lightness that keeps eight hues inside sRGB differs between them. In light the binding hues are 25 and 274; in dark it is 216. Retrofitting reliably breaks the equal-weight property in one register or the other.

Light/dark is user preference. Channel or section identity is not. Never wire them to the same switch — dark mode must not make the portal silently wear a channel's uniform.

One register per fixed canvas

An exported PNG cannot respond to prefers-color-scheme, so a 1080×1350 infographic or a 1400×1000 quote card picks one register and pins it. That is why the format examples hardcode their values while these foundation cards import the live tokens — the difference is deliberate, not an inconsistency to clean up.

Naming

Categorical slots are numbered, never named for their hue. Status tokens are named for their meaning, never numbered. The inverse rule, for the same reason: slots are reassignable, meanings are not.

Kevin's initials are lowercase — kwp, never KWP. The signature monogram is the reason. Not the domain, and not his name in prose.

docs/SPEC.md is the settled contract and the authority for all of the above. Removing or renaming a token is a major bump; the categorical count, hue placement, the layering contract, the chroma ceiling, and the text-label rule are not unilateral changes.
